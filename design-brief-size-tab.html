Size Tab — Trading Intelligence Layer

Adds the four pre-trade signals professional traders rely on — market depth, contract specs, candle footprint, and live order flow — directly inside the Size step. Plus a global hover-tooltip system bringing back v1 DotVerse's "every term has an explanation" UX.

1 · The problem

A trader sizing 10 simultaneous trades has no idea what they're walking into.

The current Size tab tells them how big their position is. It doesn't tell them whether the market can absorb the orders, what they're actually buying (1 lot of EUR/USD ≠ 1 lot of gold), or whether real money is moving with them or against them.

This is the gap between an amateur app and a professional trading platform. Pro tools — Sierra Chart, Bookmap, NinjaTrader — show all four data layers. DotVerse hides them. Users sense the lack and either over-trade (because they can't see liquidity warnings) or under-trade (because they don't trust the signals).

DotVerse v1 had partial versions of these. v2 dropped them in the redesign. This brief restores them, in a single, coherent panel.

2 · The solution

One "Trade Intelligence" panel on the Size tab, four stacked sections, all pulling live data.

Sits between the position calculator and the Multi-Trade Ladder. Read top-to-bottom in 6 seconds. Every section answers one specific trader question.

01Liquidity

Can the market absorb my orders?

Bid/ask depth + spread + verdict.

Data source
Binance order book (crypto) · Broker L2 feed via the EA (forex/stocks/commodity)
Refresh
Every 2 seconds while Size tab is open
Trader value
Tells them whether to split a $10k ladder into one order or ten. Thin book = slip badly = trades go off entry by 0.5%+.
02Contract

What does 1 lot of THIS asset actually mean?

Lot size + pip value + tick size + margin + trading hours.

Data source
Static specs per asset class (forex/stocks/commodity/crypto/index) shipped with the app — no API call
Refresh
Updates whenever the user changes ticker
Trader value
Stops the "I bought 1 lot but didn't realise it was 100 oz of gold" disaster. Especially critical for newer traders who don't know contract specs.
03Footprint

Were the recent candles driven by real or fake buyers/sellers?

Real vs Poser breakdown for the last 5 candles. v1 DotVerse signature.

How it's classified
Real Buyer = aggressive market-buys that took the ask, with volume confirmation
Poser Buyer = bid creeping up but no volume going through (limit orders, not real demand)
Real Seller / Poser Seller — same logic flipped
Data source
Existing OHLCV + tick volume from the chart. No new data needed.
Trader value
The single best signal-confirmation tool. A BUY signal on a candle dominated by Real Sellers = trap. Same setup with Real Buyers = strong setup.
04Order Flow

What's happening in the market right now?

Live tape of every trade as it fills, with size + direction + price.

Data source
Binance websocket (crypto) · Broker tick feed via the EA (forex/stocks)
Refresh
Real-time stream while Size tab is open
Trader value
Confirms or denies the trade in the last 10 seconds before pulling the trigger. Heavy buying right now = take the trade. Heavy selling = wait.

5 · How a trader uses it

Walkthrough: AAPL signal, 4H, 5-trade ladder.

1

Signal arrives — trader navigates Market → Signal → Understand → Size

Existing flow. AAPL BUY at 273.66, SL 266.51, TP 290.98. Account $10k, 5% risk, Position size auto-calculated.

2

Trader scrolls past the calculator → sees Trade Intelligence panel

Four sub-cards stack vertically. All four populate within 3 seconds of arriving on the Size tab — Liquidity + Order Flow stream live.

3

Reads top-down — each section gives a verdict in plain English

"Deep market — your $10k will fill clean." "1 lot AAPL = 100 shares." "4 of last 5 candles REAL UP — confirmed." "Strong buying right now — last 7 trades net +$X buy pressure."

4

Confidence calibrated — proceeds to Multi-Trade Ladder + Submit All to MT5

If any section flags red ("thin liquidity" or "FAKE UP last candle"), they pause or skip the trade. Otherwise full ladder fires.

6 · Global hover-tooltip system

Bringing back v1's "every term has an explanation" UX.

Built once as a reusable data-tip attribute. Any element that gets the attribute auto-shows a tooltip on hover. Applied across every page.

Try it: hover any term below.

Confluence 75% · R:R 1:2.4 · ATR 3.2 · Half-Kelly 2.5%

Coverage scope: every metric, button label, technical term across Market / Signal / Scanner / Understand / Size / Act / Automations / Track Record. ~80 unique terms. Roughly 2 hours of writing tooltip copy + 30 minutes wiring the attribute.

7 · Trade-offs and risks

What we're committing to and where the limits are.

Liquidity (Section 01)

Crypto: Binance public REST API — free, no auth, instant.
Forex/stocks: Requires the EA to push order-book depth — adds payload to /api/mt5/push. ~2KB overhead per heartbeat. Acceptable.

Contract specs (Section 02)

Static dataset of ~150 symbols shipped with the app. No external dependency. Easy to maintain.

Real vs Poser (Section 03)

Classification uses heuristics — close-vs-open + volume + range — not true bid/ask data. Will be ~85% accurate vs a Sierra Chart-style true footprint. Trade-off: zero new data infrastructure required.

Live order flow (Section 04)

Heaviest build. Crypto via Binance websocket is straightforward. Forex/stocks need the EA to stream tick data — increases EA→backend traffic. Recommendation: ship crypto first, forex/stocks as v2.
