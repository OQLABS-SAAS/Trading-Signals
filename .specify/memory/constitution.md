# DotVerse Constitution

## Core Principles

### I. Beginner-First
Every element must explain itself. No jargon without context. Every number needs a "what this means" and "what to do next."

### II. Zero Fake Data
Every data point comes from a real API or is honestly marked unavailable. No hardcoded values presented as real.

### III. Design Before Code
Spec and plan approved before any implementation. No "I'll figure it out while building."

### IV. Verify Before Deploy
Every change is tested against the live app before telling the user it's done.

### V. Per-Commit Approval
Every push needs explicit "deploy" from the project owner.
